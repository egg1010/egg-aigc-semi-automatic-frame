# 视频模块调度器（VIDEO MODULE DISPATCHER）

**作用域**：仅限视频模块操作

## 步骤1｜初始化

1. 分段时长
   - 如果没有明确要求每一集的每一段是多少秒 → 默认每一段是 30秒
2. 阅读规范 ★ 启动必读
   - 运行 根目录 `跟新规范.md`（每次重新阅读 `规范/项目规范.txt` 与全部格式文件，含 `规范/流程状态机.md`；附带阅读 `规范/多集要求.txt`，寻找与异常规则见该文件）
   - ★ 重点：阅读参数和规范，做出选择
3. 文件规范
   - 工作目录下有对应的剧集文件夹（可能是 xxx戏文件夹，也可能是数字命名）
   - 里面有 资产图 和 剧情
   - 剧情来源：文本拆分模块输出的分段文件（数字文件夹内的 x-a），按 集 进入
   - 资产图位置：单集文件夹内的 `资产图` 文件夹（文本拆分模块每集自动创建）
   - 最后在对应剧集文件夹内创建 提示词文件
   - 如果没有找到 剧集文件夹 → 异常 → 跳到 收尾，之后终止运行
4. ★ 架构文件缺失处理：`通用模块/材质模块.txt`、`通用模块/皮肤模块.txt`、`通用模块/光线模块.txt`、`通用模块/默认光线设计.md`（光线设计层）、`通用模块/色彩模块.txt`、`通用模块/联动模块.md`、`通用模块/图片分析限制模块.md`（图片模式）、`视频模块/基础格式.txt`、`视频模块/重构基础模块.md`（重构模式）预设路径不存在 → **先尝试寻找**（工作区范围内搜索同名文件）→ 确实找不到才异常 → 跳到 收尾：按 `规范/异常设计.md` 写入 `异常/日期异常.md` → 直接终止运行（不编造路径、不用默认顶替、不跳过继续）。四库查阅顺序=设计顺序：材质→皮肤→光线（含设计）→色彩（依据 联动模块【联动总则】第1条）

## 步骤2｜进入单集文件夹（可能是 xxx戏文件夹，也可能是数字命名）

**判断模式（优先级：声明的 video_input_mode > 文件夹状态自动判定）**：

- 如果单集文件夹已有提示词文件且含「重构」标记 → 重构模式：执行 `视频模块/重构基础模块.md`，完成后跳到 步骤4 收尾
- **声明的 video_input_mode**（由 全局调度器/用户 声明，记录在状态文件）：
  - `asset_reference`（图片模式）→ 准入：该集资产图文件夹有图；缺图处理见下方【缺图准入规则】
  - `text_only`（文本模式）→ 准入：无资产图，或用户明确选择「暂不补全」（即使文件夹内有图也按声明执行，并在报告中标注）
  - `hybrid`（混合模式）→ 准入：用户明确接受部分资产有图；有图资产列【资产参考】，无图资产按文本构建（来源标 `文本:剧本描述`）
- **未声明** → 自动判定：`资产图` 文件夹缺失或为空 → 文本模式；内有图片 → 图片模式（无输入图片分析限制 → auto模式，由图片分析限制模块自动判定限制）
- 声明与文件夹状态冲突（例：声明 asset_reference 但文件夹为空）→ **不静默改变**：发起选项「补图后继续 / 降级 hybrid 或 text_only 继续 / 终止」；用户选择后写入状态
- ★ 一致性要求：相同配置下，全局调用与直接调用本模块行为一致——统一按「声明优先、自动判定兜底、缺图按准入规则」，全局处不再单独设「缺图即终止」

**缺图准入规则（三种模式统一口径）**：

| 模式 | 缺图处理 |
|---|---|
| asset_reference | 段内清点发现缺图 → 记异常（段号+缺失资产）+ 该资产按文本构建继续（等效降级 hybrid），**不终止本段输出**；关键人物资产全缺 → 发起选项（补图/转 text_only/终止） |
| text_only | 不适用（无图即准入条件） |
| hybrid | 缺图为常态 → 逐项记异常即可，不降级、不终止 |

## 步骤3｜运行

按 步骤2 判定的模式执行（hybrid 按 图片模式 流程执行，缺图资产按文本构建并逐一记异常）。

- 画幅/比例：如果没有明确说明 → 不写（两种模式一致）
- ★ 详细度总要求（两种模式一致）：材质逐条设计、影调逐槽写满；无图模式详细度不得低于图片模式
- ★ 同场衔接：多个戏在同一个场景内 → 必须考虑上下场衔接——场景/站位设计/光线/时间状态/道具位置 沿用上一场的结束状态作为下一场的起点（变化处写明变化原因），提示词中把承接的具体状态**就地展开写全**（禁止「同上一场」「与第N段一致」类引用语——见 `视频模块/基础格式.txt` 注意事项 10）
- ★ 穿防排查（同场景多段戏，设计前强制）：选参数之前先逐项对齐上一场结束状态——①服装发型妆容 ②光线方向/色温/时间段 ③道具位置与状态（损坏/移动过要保持） ④人物位置/朝向/轴线 ⑤天气与窗外环境——任何不一致必须有剧情原因（时间流逝/换装/剧情动作）并写入提示词，否则视为穿帮，设计时即修正
- ★ 剧本忠实硬性限制：分段文件（x-a）为只读源——台词、剧情事实、人物、动作、因果 忠实原文，禁止改写／删减／增添／概括缩写；所有段落逐段覆盖，不遗漏任何场次与台词；唯一例外 = 用户明确的修改要求（改动处在对话中说明改了什么、为什么）
- ★ 不得忽略原剧本设计：剧本已写明的设计（场景布置／人物外形与服装／道具外观设定）是第一优先输入——必须原样进入参数设计与对应槽位，禁止无视剧本设定自行发挥或替换成自建设计；剧本未写明处才由 通用模块四库 补全（标注来源）

**图片模式**

1. 确认风格（没有明确要求 → 默认「写实 实拍风格 电影感」）
2. `通用模块/图片分析限制模块.md` → 输出【图片分析报告】（材质清单表 + 站位分析表）→ 仅在对话内持有（不落盘），完整传入 联动模块
3. `通用模块/材质模块.txt`
4. `通用模块/皮肤模块.txt`
5. `通用模块/光线模块.txt` + `通用模块/默认光线设计.md` → **必须完成光线设计产出**（六项落参数设计表：流派锁定声明/人物光签名档案/场次光弧表/光池标注/影向声明/动态范围取舍——阅读≠设计，未产出=后续自检拦截）
6. `通用模块/色彩模块.txt`
7. `通用模块/联动模块.md` → 按【联动规则】联合设计参数（互相配合，禁止独立选参；图片分析报告逐项落进「参数设计表」：每个主材质至少一行 + 站位行；通过【自检清单】含第 12 条光线设计决策检查）
8. ★ 段内清点（基础格式输出前检查）：逐段剧情清点出现的 **人物／场景／道具**，每段列出名单 →
   - 对照 资产图文件夹：出现但缺资产图 → 按【缺图准入规则】处理（asset_reference：记异常 + 该资产按文本构建继续，不中断本段输出）
   - 清点名单决定【资产参考】声明范围：只声明该集实际出现的资产；正文引用与名单一致，禁止写未出现的人物/道具
9. 最后 → 遵守 `视频模块/基础格式.txt` 输出提示词文件，位置是单集文件夹

**文本模式**

1. 确认风格（没有明确要求 → 默认「写实 实拍风格 电影感」）
2. `通用模块/材质模块.txt`
3. `通用模块/皮肤模块.txt`
4. `通用模块/光线模块.txt` + `通用模块/默认光线设计.md` → **必须完成光线设计产出**（六项落参数设计表：流派锁定声明/人物光签名档案/场次光弧表/光池标注/影向声明/动态范围取舍——阅读≠设计，未产出=后续自检拦截）
5. `通用模块/色彩模块.txt`
6. `通用模块/联动模块.md` → 按【联动规则】联合设计参数（互相配合，禁止独立选参；★ 无图：从剧本提取主要承载物/材质逐条设计进参数设计表，来源标 `文本:剧本描述`；通过【自检清单】含第 12 条光线设计决策检查）
7. ★ 段内清点（基础格式输出前检查）：逐段剧情清点出现的 **人物／场景／道具**，每段列出名单 →
   - 对照 资产图文件夹（有图时）：出现但缺资产图 → 按【缺图准入规则】处理（记异常 + 该资产按文本构建）
   - 清点名单决定【资产参考】声明范围（有图时）与 正文引用边界：禁止写未出现的人物/道具
8. 最后 → 遵守 `视频模块/基础格式.txt` 输出提示词文件，位置是单集文件夹

## 状态与门禁

- 启动状态判定：读工作区 `状态/流程状态.json`（缺失 → `python 工具/校验器.py init <工作区> --unit <单元>`）→ 确定 unit 当前阶段与 video_input_mode；VIDEO_PROMPTS_READY 已完成且产物版本未变 → 默认跳过（用户明确要求重做 → 强制重跑，版本 +1）
- 提示词收尾（硬性，每集/每段批次）：
  1. **写状态**：`python 工具/校验器.py advance <工作区> --unit <单元> --stage VIDEO_PROMPTS_READY --mode <资产模式> --artifact video_prompts=<相对路径>`（版本自增；模式未声明时先按【缺图准入规则】确定）
  2. **跑校验**：`python 工具/校验器.py check <工作区> --stage VIDEO_PROMPTS_READY --unit <单元>`（槽位完整性/字数上限/资产引用/跨段引用禁令/镜头编号连续）
  3. **阶段执行报告**（对话输出）；校验 ERROR 未清零 → 不得交付本轮输出
- **逐段台账**：每段提示词完成 → 用 fact 命令写 `end_state`（段尾交接状态：人物位置/道具持有/光线时段），供下一段与后续集衔接
  - `python 工具/校验器.py fact <工作区> --unit <单元> --id <单元>.<主体>.end_state --subject <主体> --field end_state --value <一句话> --source 提示词:<文件名>`
- **复核**：用户复核通过 → `advance ... --stage REVIEWED`（→ DONE）；退回 → 仅重跑受影响段（版本 +1），其余段不动
- 阶段契约与失败策略见 `规范/流程状态机.md`；数据契约见 `规范/数据契约.md` §3.4

## 步骤4｜收尾

1. 无异常 → 除业务交付物与状态文件外不写任何文件，正常结束
2. 有异常（含 找不到剧本中对应的资产图）→ 按 `规范/异常设计.md` 写入 `异常/日期异常.md`（失败同时写入状态 `failures`）
