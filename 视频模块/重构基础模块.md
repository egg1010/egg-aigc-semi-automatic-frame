# 重构基础模块（RESTYLE BASE MODULE）

**定位**：重构体系的基础模块（执行协议）。对已生成的提示词做受控重构。
**服务对象**：根目录 高层接口（重构）+ 图片/视频 调度器的重构模式。
**原则**：新风格参数优先取自 通用模块（材质/光线/皮肤/色彩）+ 联动模块。

## 触发与范围语法

写在提示词条目后面（同一行或紧邻下一行），或由高层接口转发：

| 写法 | 范围 |
|---|---|
| `重构 图片N` | 只重构第 N 张图片（人物场景提示词表中对应条目） |
| `重构 视频N` | 只重构第 N 段视频（对应镜头N/分段N） |
| `重构 所有图片` | 重构提示词表中全部图片提示词 |
| `重构 所有视频` | 重构单集提示词文件中全部视频提示词 |

## 两种模式

| 指令 | 模式 | 可修改范围 |
|---|---|---|
| 只写「重构」 | 普通重构（默认） | 仅白名单五项 |
| 指令中含「联动」（如 `重构 图片2 联动`） | 联动重构 | 白名单五项 + 联动层 |

- **联动重构**：为配合 图片模块/视频模块 的已有条目（资产图、镜头衔接、声音时间轴等），允许额外修改 联动层——镜头景别、机位、镜头设计（运镜与景别组合）、构图、空间布局、动作、表情等
- **联动重构的风格轴（可单独控制）**：
  - 用户给了新风格 → 风格层 + 联动层 一起改
  - 用户没给新风格 → **画面风格保持不变**（原风格参数原样保留），只改 联动层（镜头设计）
- 联动层每处改动必须注明原因（对齐哪个模块的哪一条），无对齐理由的改动视为越权

## 格式轴（第三维度，默认格式不变）

指令含「格式变」（或指明目标格式，如 `转 基础格式`）→ 允许修改格式。三种组合：

| 指令 | 风格 | 格式 |
|---|---|---|
| `重构 X 格式变` | 变 | 变 |
| `重构 X 联动 格式变` | 变（未写风格则不变） | 变 |
| 只写 `格式变`（无新风格、无联动） | **不变** | 变（纯结构转换） |

- 默认转换目标：`视频模块/基础格式.txt`（文本拆分单集文件夹的标准格式）；用户指明其他格式则按指明执行
- **格式重构 内容不变**：内容语义禁止丢失——风格参数、镜头、台词、逻辑约束必须完整迁移到新格式的对应槽位
- 迁移后自检：新格式槽位与原内容一一对应，缺失或无法安放的内容 → 按 `规范/异常设计.md` 写入，并询问用户

## 设计重构（第四选项：视听层重设计）

指令含「设计重构」→ AI 重新设计 **视听语言**：镜头设计（运镜）、景别、构图、声音时间轴、画面节奏、人物表演设计

- **内容语义不变**：台词、逻辑约束、事实、道具、条目数量与顺序 原样保留
- 风格默认不变（用户同时写了新风格 → 叠加修改）
- 格式默认不变（写了「格式变」→ 叠加转换）
- 每处设计改动标注：改了什么 + 为什么（对齐剧情情绪/上下镜头/声音衔接）

## 交互规则（发起选项，而非文本输入）

AI 在执行前必须**主动向用户发起选项**（按钮式点选），不要求用户输入文本指令：

| 场景 | 发起的选项 |
|---|---|
| **用户啥都没说** | **全选项表**（见下，零输入入口） |
| 「设计重构」 | 2-3 个设计方案：方案名 + 视听设计摘要 + 一句画面预期 |
| 「内容重构」 | 2-3 个内容修改方案：改动点（台词/逻辑/事实/道具）+ 改法 + 对剧情影响 |
| 「重构」未写风格（普通重构） | 3 个候选风格方案（风格名 + 参数摘要 + 画面预期） |
| 目标/范围无法判定 | 目标选项：图片N / 视频N / 所有图片 / 所有视频 |

**全选项表**（用户逐项点选；**每个选项必须附带一句作用说明，禁止只列名称**）：

1. 重构类型（**可多选**，按【多选规则】叠加执行）：
   - 普通重构 → 只改 风格五项（画面风格/材质/色彩/光线/皮肤表现），镜头、台词、格式全部不动
   - 联动重构 → 改风格（可选）+ 镜头景别/机位/构图/动作/表情（配合资产图与上下镜头衔接）
   - 设计重构 → 重设计 视听语言（镜头设计/景别/构图/声音时间轴/画面节奏/人物表演），台词与逻辑不变
   - 内容重构 → 修改 台词/逻辑约束/事实/道具（剧情内容层），改动必须自洽
   - 格式变 → 只转换 提示词格式（如转 基础格式.txt），内容一字不变
2. 范围：图片N（只改第 N 张图）/ 视频N（只改第 N 段视频）/ 所有图片 / 所有视频
3. 风格：保持不变 / 3 个候选风格（每个候选附 参数摘要 + 画面预期）

**多选规则**：重构类型可多选（不冲突即叠加执行）：

- 普通重构 + 联动重构 → 按 **联动重构** 执行（联动包含普通范围，取并集）
- 联动重构 + 设计重构 → 镜头部分合并为一次视听设计，对齐理由与设计理由标注保留
- 其余组合（设计+内容、联动+格式变、普通+设计、内容+格式变…）→ 直接叠加，各层各改各的
- 任意组合下 条目数量与顺序 仍然永远禁止；组合后参数仍须走 联动模块 流程

**资产变化流程**：重构过程中需要新增或变化的资产（新参考图、新道具资产、新人物资产图）→ AI 必须停下 向用户发起 资产选项：

- 用户提供 **资产路径**（指向已有资产图文件），或
- 用户 **上传** 图片/文件
- 未提供前 相关改动**挂起**并说明原因；禁止凭空编造资产，禁止用无关图片顶替
- 提供后继续执行，并把资产路径记入对应条目

- **每个选项必须附带「自定义输入」**：类型 / 范围 / 风格 / 设计方案 / 内容方案 / 资产，全部允许用户直接输入自己的要求：
  - 点选 + 补充输入 → 以点选为基础，输入内容作为附加要求合并执行
  - 纯文本输入 → 直接按用户要求执行（仍受对应模式的护栏约束）
- 选项内参数必须取自 通用模块四库 + 联动模块（标注 R 编号与体系）；用户自定义输入的要求优先于候选参数

## 执行规则（硬性）

1. 可修改范围（白名单，仅此五项）：
   - 画面风格
   - 材质
   - 色彩
   - 光线
   - 皮肤表现（与以上联动的部分）
2. 禁止修改（黑名单，分层放行）：条目数量与顺序**永远禁止**；输出格式结构默认禁止（「格式变」按【格式轴】放行）
   - 视听层（镜头景别、机位、构图、空间布局、人物位置与朝向、动作、表情、声音时间轴）→ **普通重构**下禁止；联动重构／设计重构放行且必须注明对齐或设计理由
   - 内容层（台词、逻辑约束、事实、道具位置与状态）→ **仅内容重构**放行且必须注明改动理由；其余任何模式一律禁止
3. 白名单修改不得产生黑名单副作用（例：改光线不得连带改变景别或站位描述）
4. 必须走 联动模块 流程：先出「参数设计表」（标注体系 影视/游戏，参数优先取自通用模块）→ 通过【自检清单】→ 再改写提示词
5. 重构结果原地替换对应条目，其余条目一字不动

## 图片分析支持（可选）

- 目标条目带参考图 → 运行 `通用模块/图片分析限制模块.md`：仅提取材质与站位，用于保持重构后材质不漂移
- 新风格仍由 用户要求/通用模块参数 决定，禁止从参考图提取风格
- 没有参考图 → 纯文本重构

## 新风格来源

- **普通重构**：用户在「重构」后写明新风格 → 按要求执行
- **普通重构**未写风格 → 发起 3 个候选风格选项（见【交互规则】）
- **联动重构**未写风格 → 不出候选：画面风格保持不变，只改 联动层（镜头设计）
- 指令含「格式变」且未写风格 → 不出候选：风格不变，只做格式转换
- 指令含「设计重构」且未写风格 → 不出候选：风格不变，先发起设计方案选项

## 范围与冲突

- `重构 所有图片/视频`：整体风格必须统一（同一套参数设计表），个别条目可在总表下做差异化微调
- 重构参数与原构图/逻辑约束冲突（例：夜景风格但构图写白天窗外）→ 按 `规范/异常设计.md` 写入；问题过于严重 → 询问用户
