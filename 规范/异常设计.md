# 异常设计（EXCEPTION DESIGN）

**定位**：异常体系唯一规范文件，隶属 项目规范（规范/）。定义全流程的写文件边界与异常记录格式；高层接口（跟新规范.md / 各调度器 / 设计与重构）只引用本文件，不自行定义格式。

## 写文件边界（落盘白名单）

- 正常运行只允许**四类写入**：① 业务交付物（拆分文件/资产表/提示词文件/输出表格）② 状态文件（工作区 `AI数据/状态/流程状态.json`、`AI数据/状态/连续性台账.json`——时机与结构按 `规范/流程状态机.md`，属业务状态记录，不属中间产物）③ 异常文件（按【异常记录规范】写 `AI数据/异常/日期异常.md`）④ **受控记忆库**（`AI数据/data/projects/<project_id>/project.db`——仅由受信执行器写入，按 `规范/流程状态机.md` 第六节的写入纪律）
- 中间产物（参数设计表/自检清单/阅读确认清单/深挖对比/图片分析报告/清点名单）只在对话输出，不落盘
- 白名单之外任何写入 = 违反本规范 → 按【异常记录规范】记录

## 异常记录规范

- 唯一异常位置：`AI数据/异常/` 文件夹 —— 不存在则新建（规范里只有异常设计，异常文件不进规范文件夹）
- 文件命名：每次异常写入 `AI数据/异常/日期异常.md`，文件名 = 日期 + 异常.md（如 `2026-09-10异常.md`）；同日多次异常 → 追加到当天文件，禁止另建其他名字的异常文件
- 极简格式，每条异常固定 3 行（有查找过程 +1 行）：

```text
[MM-DD HH:MM] 发起方>步骤
! 问题：一句话
> 已查找：位置1>位置2
= 处理：终止｜挂起｜已询问用户
```

- 禁止：段落式描述、多层标题、多余空行、重复上下文

## 结构化异常字段（机器可查询，新增）

人工可读的异常报告**保留**（上面 3 行格式不变）；**另外**将机器可查询的异常状态写入记忆库与状态记录，字段如下：

| 字段 | 含义 |
|---|---|
| `error_code` | 机器可判的错误码（见下表） |
| `run_id` | 本次运行标识，用于恢复与重试定位 |
| `stage_id` | 出错的阶段（CREATED…DONE） |
| `project_id` | 项目标识 |
| `source_refs` | 相关证据块/原文引用，便于追溯 |

**错误码约定**（与校验层、记忆层一致）：

| error_code | 触发场景 | 处理 |
|---|---|---|
| `PROJECT_NOT_FOUND` | 项目未初始化 | 终止，提示先 init |
| `SCENE_NOT_FOUND` | 引用了不存在的场次 | 终止该步骤 |
| `ENTITY_NOT_FOUND` | 引用了不存在的实体 | 终止该步骤 |
| `EVIDENCE_NOT_FOUND` | 事实变更缺少可追溯原文 | 拒绝提交 |
| `EVIDENCE_CROSS_PROJECT` | 证据块不属于本项目 | 拒绝提交 |
| `CONFLICT_STATE` | 预期旧值与当前状态不一致 | 拒绝并回滚，提示重读状态 |
| `HISTORICAL_EDIT_REQUIRES_REPLAY` | 回写早于当前状态的场次 | 挂起，需重放后续事件或建分支 |
| `IDEMPOTENCY_PAYLOAD_MISMATCH` | 同幂等键不同内容 | 拒绝提交 |
| `CERTAINTY_NOT_EXPLICIT` | 非 explicit 事实试图进入正式状态 | 挂起，待用户确认 |
| `CROSS_PROJECT_DENIED` | 跨项目引用文档/状态 | 拒绝 |
| `RULE_CHANGED_UNAPPROVED` | 规范已变但未人工审核 | 禁用旧缓存，需审核后重跑 |
| `RULE_CACHE_INVALIDATED` | 规范哈希变化导致缓存失效 | 重读规范并重算受影响产物 |

- 严重错误进入 `failed` / `awaiting_review`（对应状态文件 `failures` 与挂起点），**不能悄悄继续执行下游阶段**

## 异常处理原则

- 先尝试寻找（预设路径 → 工作区搜索同名文件）→ 确实找不到才记异常
- 记异常后按各流程规则处理：终止／挂起／询问用户
- 不编造路径、不用默认顶替、不跳过继续
- **规范/规则冲突** → 按 跟新规范【规范优先级与规范清单】的优先级链裁决（安全/硬约束 > 项目规范 > 全局流程 > 模块规范 > 默认策略）；下层禁止覆盖上层硬约束；无法裁决 → 记异常
- **阶段失败/恢复** → 按 `规范/流程状态机.md` 写入状态 `failures`，按该阶段 failure_policy 处理（终止/挂起/降级继续/询问用户）

## 启动例外（不写异常文件，AI 直接说明后终止）

- 启动时 规范文件夹缺失 → AI 直接说「规范文件夹缺失」→ 终止
- 启动时 规范文件（项目规范.txt）缺失 → AI 直接说「规范文件缺失」→ 终止
- 原因：异常记录本身依赖规范体系存在，体系缺失时无处落盘
