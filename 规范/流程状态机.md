# 流程状态机（FLOW STATE MACHINE）

**定位**：全流程执行保障规范——定义阶段状态机、阶段执行契约、状态文件与失败恢复策略。领域规则仍由各模块 Markdown 负责；本文件只负责「状态转移与结果校验」。
**服务对象**：全局调度器与 文本/图片/视频 模块调度器（每次运行必读）。
**配套**：字段级结构契约见 `规范/数据契约.md`；机械校验由 `工具/校验器.py` 执行。

## 一、阶段状态机（每个工作单元一个 stage）

```text
CREATED → SCRIPT_PARSED → ASSETS_INDEXED → IMAGE_PROMPTS_READY → VIDEO_PROMPTS_READY → REVIEWED → DONE
```

- **工作单元（unit）**：一集（以工作区实际集文件夹名为 unit 名，如 `第1集`／`1`）；用户指定其他范围时按用户范围拆分登记
- 阶段**只前进不回退**；回退（重做）必须由用户指令触发（重构／重跑），重跑时版本 +1
- **跳级**仅当用户显式指定执行范围（如「仅视频模块」）→ 跳过的阶段记入 `stages_skipped`，且必须先满足该阶段的 required_inputs
- 阶段与模块的对应：
  - `CREATED`：任务建立（全局调度器初始化）
  - `SCRIPT_PARSED`：文本模块·文本拆分完成
  - `ASSETS_INDEXED`：文本模块·资产表完成
  - `IMAGE_PROMPTS_READY`：图片提示词模块完成
  - `VIDEO_PROMPTS_READY`：视频模块完成（逐段提示词产出）
  - `REVIEWED`：用户复核通过（在对话中确认）→ `DONE`

## 二、阶段执行契约（每阶段五要素，硬性）

| 阶段 | required_inputs 必需输入 | outputs 产物 | validators 校验（自动+人工） | next_steps | failure_policy 失败策略 |
|---|---|---|---|---|---|
| CREATED | 工作区路径；剧本源文件（只读）；执行范围 | `状态/流程状态.json` 初始化（unit 记录） | 剧本可定位；工作区可写状态目录 | SCRIPT_PARSED（或按用户范围） | 找不到剧本 → 发起剧本来源选项；取消 → 挂起（状态记 `failures`） |
| SCRIPT_PARSED | 剧本源文件（只读） | 每集分段文件（`x/x-a`，按 自定义拆分格式规范）；每集 `资产图` 文件夹 | 校验器 `--stage SCRIPT_PARSED`；分段完整覆盖、无逻辑冲突（只查不改） | ASSETS_INDEXED | 逻辑冲突 → 异常 + 终止拆分；找不到规范 → 按 跟新规范 规范清单 |
| ASSETS_INDEXED | 分段文件 | 资产表（场景/人物/道具 分区） | 校验器 `--stage ASSETS_INDEXED`；资产名唯一稳定；材质标注齐全 | IMAGE_PROMPTS_READY | 资产无法判定 → 询问用户；拒绝 → 挂起并记状态 |
| IMAGE_PROMPTS_READY | 资产表；风格要求（缺省=写实实拍电影感） | 资产图提示词（人物场景提示词表） | 校验器 `--stage IMAGE_PROMPTS_READY`；槽位完整性/负面提示词/参数可溯源（联动自检清单） | 用户补全资产图 → VIDEO_PROMPTS_READY | 参数无法判定 → 异常；严重 → 询问用户 |
| VIDEO_PROMPTS_READY | 分段文件；资产图（按 video_input_mode）；资产表 | 每段提示词文件（基础格式） | 校验器 `--stage VIDEO_PROMPTS_READY`；槽位完整性/字数上限/资产引用/跨段引用禁令；穿防五项 | REVIEWED | 缺资产 → 按模式准入规则（见 视频模块/调度器 步骤2）；ERROR 未清零 → 不得交付 |
| REVIEWED | 提示词文件 | 复核结论（通过/退回，对话输出） | 人工复核：忠实原文/穿防/逻辑 | DONE 或退回重跑 | 退回 → 仅重跑受影响段（版本 +1），其余段不动 |
| DONE | — | — | 全部阶段通过 | — | — |

- **门禁规则（硬性）**：每阶段收尾必须运行校验器；`ERROR` ≥ 1 → 不得进入下一阶段（修复重跑，或按异常设计记录后挂起）；`WARN` 允许继续但必须写入阶段执行报告
- **阶段执行报告**（对话输出，不落盘）：阶段名｜校验器结果（ERROR/WARN 计数）｜状态变化（旧 stage → 新 stage）｜异常清单（如有）

## 三、状态文件（业务状态落盘；全流程唯一新增允许写入）

状态文件位于**工作区**根目录 `状态/` 下，共两个，结构契约见 `规范/数据契约.md`：

| 文件 | 层 | 内容 | 写入时机 |
|---|---|---|---|
| `状态/流程状态.json` | 流程层 | 每 unit：stage / stages_done / stages_skipped / video_input_mode / artifacts（产物路径与版本）/ failures / history | ① 初始化时创建 ② 每个阶段收尾点 ③ 重跑/重构（版本 +1）④ 失败与挂起记录 |
| `状态/连续性台账.json` | 业务层 | 会变化的事实：服装/持有物/位置/状态/时间线节点/段尾交接状态（id/subject/field/value/source/confidence/verified/version） | ① 拆分收尾（从剧本抽取关键事实初版）② 资产表收尾（仅补录需跟踪状态的资产：服装/可流转道具）③ 逐段提示词收尾（段尾交接状态 end_state）④ 用户确认（verified=true）⑤ 重构（版本 +1 + 改动原因）⑥ 冲突标记 |

**写入纪律（硬性）**：

1. 只写「已确认事实」；推断必须 `confidence=inferred`；禁止把推测升级为 `confirmed`（沿用 理解模块【事实与推断隔离】）
2. **状态文件不替代重新阅读**：每次运行仍按 跟新规范 重读规范、格式与源文件；状态文件只作**状态判定与断点恢复**依据，禁止用状态文件内容代替阅读/替代原文引用
3. 与源文件（剧本/资产表/提示词文件）冲突 → 以源文件为准，并在 `conflicts` 数组标记（含冲突双方与来源），严重时按 `规范/异常设计.md` 处理
4. 禁止借状态文件之名写入任何其他内容（分析报告/参数设计表/清单等仍为对话内中间产物）
5. 同日多 unit 更新 → 更新 `updated_at`；文件保持 UTF-8 JSON，缩进 2 空格

**状态与校验的标准命令（从框架根目录执行；检查项见 `工具/校验器.md`）**：

```text
初始化：  python 工具/校验器.py init    <工作区> --unit <单元>
推进：    python 工具/校验器.py advance <工作区> --unit <单元> --stage <阶段> [--mode <资产模式>] [--artifact 名称=相对路径 ...]
台账：    python 工具/校验器.py fact    <工作区> --unit <单元> --id <事实id> --value <内容> --source <来源> [--subject <主体> --field <字段>] [--verified]
失败：    python 工具/校验器.py fail    <工作区> --unit <单元> --reason <原因> [--action 终止|挂起|已询问用户]
门禁：    python 工具/校验器.py check   <工作区> --stage <阶段> [--unit <单元>]
```

- 状态文件**优先经校验器的 init / advance 写入**（结构统一、版本自增）；手工编辑仅在命令不可用时允许，且必须通过 `check` 复验
- 校验器不可用 → 降级为清单自查 + 按 `规范/异常设计.md` 记异常（见 跟新规范 规范清单）

## 四、失败恢复（断点恢复）

- 失败/挂起 → 写入 `failures[]`（阶段｜原因｜受影响产物｜处理：终止/挂起/已询问用户）
- 恢复（用户继续时）：**只重跑受影响阶段**——已完成且产物版本未变的阶段跳过（读 `stages_done` 与 `artifacts.version` 判定）；重跑前重读该阶段 required_inputs
- **版本防护（防旧覆盖新）**：写入任何产物前，比对目标文件版本与状态记录——目标被人为或更晚任务修改过（版本更新）→ **不覆盖**，先询问用户或记异常
- 恢复后阶段执行报告需注明：恢复点（从哪个阶段续跑）、跳过阶段清单

## 五、与「流程零落盘」的关系（修订口径）

- 「零落盘」继续适用于一切**推理草稿**：规范/格式阅读、图片分析报告、参数设计表、自检清单、清点名单、阅读确认清单、深挖对比等——一律只在对话输出
- **允许的写入共四类**：① 业务交付物（拆分文件/资产表/提示词文件/输出表格）② 状态文件（本文件第三节）③ 异常文件（`规范/异常设计.md`）④ **受控记忆库**（本文件第六节，`data/projects/<project_id>/project.db`）
- 四类之外任何写入 = 违反 规范/异常设计.md，按异常处理

## 六、受控记忆库（状态存储层）

**定位**：在保留本文件第一至四节**状态机不变**的前提下，新增 SQLite 记忆层承担「事实可追溯长期记忆」。
阶段推进仍由本文件定义的 stage 机器与 `工具/校验器.py` 的 init/advance/fact/fail/check 负责；记忆库**不接管阶段状态机**，只负责业务事实的存储、检索与防污染。

```text
工作区/
├── 状态/                          # 流程层与业务层状态（本文件第三节，保留）
└── data/projects/<project_id>/
    └── project.db                 # 受控记忆库（SQLite，本层新增）
```

### 6.1 单一事实来源（禁止越权覆盖）

| 数据 | 表 | 地位 |
|---|---|---|
| 原文 | `documents` / `chunks` | **最初事实来源**；不得由摘要覆盖 |
| 已批准事件 | `events` | 剧情状态变更依据；保留原始证据 |
| 当前状态 | `state_current` | 已批准事件的**物化投影**，不是原始事实 |
| 摘要 | `summaries` | **可重新计算**的派生数据；不得反向修改原文或事件 |

### 6.2 写入纪律（硬性）

1. **AI 只能提出候选，不得写库**：模型输出的事实变更必须经 `propose_event` → 校验 → 审批 → `approve_event` 事务提交
2. **证据必填**：每条事实变更必须带 `evidence_chunk_id` 指向真实原文；摘要不能替代原文
3. **旧值必须匹配**：提交前核对 `expected` 与当前状态；不一致 → 拒绝并回滚，状态不受污染
4. **原子性**：一次事件涉及的多字段全部成功或全部回滚
5. **幂等**：同一 `idempotency_key` 重试不重复应用；同键不同内容 → 拒绝
6. **certainty 分级**：`explicit` 方可进入审批队列；`inferred` 默认不进正式状态，需用户确认；`unknown` 不得进入
7. **历史回写保护**：不得用早于当前状态的场景直接覆盖头部状态；需重放后续事件或创建分支版本
8. **同库隔离**：`project_id` 参与全部主键与外键；不得仅凭资产名称跨项目作主键

### 6.3 记忆库的标准命令（从框架根目录执行）

```text
初始化：  python runtime/main.py init    --project <项目id> [--name <名称>]
导入原文：python runtime/main.py ingest  --project <项目id> --path <文件> [--rel-path <记录路径>] [--scene <场次id> --scene-order <N>]
抽候选：  python runtime/main.py extract --project <项目id> --chunk <证据块id>
查状态：  python runtime/main.py state   --project <项目id> [--scene <场次id>] [--entity <实体id>]
查轨迹：  python runtime/main.py timeline --project <项目id> --entity <实体id>
检索：    python runtime/main.py search  --project <项目id> --query <关键词>
待审：    python runtime/main.py pending --project <项目id>
校验：    python runtime/main.py verify  --stage <阶段> --input <json文件> [--project <项目id>]
规范版本：python runtime/main.py rules   [--save|--diff]
```

### 6.4 与「状态文件」的分工

- `状态/流程状态.json`、`状态/连续性台账.json`：保留，继续由 `工具/校验器.py` 读写，承担**断点恢复**与**阶段判定**
- `project.db`：承担**事实长期记忆、证据追溯、防污染**；不得用作阶段推进依据
- 两者冲突 → 以**源文件（剧本/资产表/提示词）**为准；涉及已确认事实的冲突按 `规范/异常设计.md` 记录并交用户裁决
