# 数据契约（DATA CONTRACT）

**定位**：核心中间产物与状态文件的字段级结构契约。Markdown/自然语言文档是可读视图；本文件定义**机器可校验**的结构，由 `工具/校验器.py` 机械执行。
**服务对象**：各调度器（阶段门禁时对照本契约）、校验器、重构模块。
**原则**：字段尽量少而硬；命名以「资产名」为跨阶段引用主键（不用数字 ID，避免污染提示词）；缺失字段报错可定位。

## 〇、通用规则

1. **资产名**（人物/场景/道具/空间/比例）：唯一、稳定、简短可读；一经确认**不得随意改名**（改名 = 新资产，需全链路同步并记异常）；同一名字在 资产表、资产图提示词、提示词【资产参考】、状态台账中必须指向同一对象
2. **来源标注**（沿用 理解模块【事实与推断隔离】）：`剧本:<集>-<段>`／`用户:<日期或对话指代>`／`资产表`／`提示词:<文件名>`／`推断`——一切落盘事实必须带来源，可回溯
3. **枚举值**（校验器强校验，非法值 = ERROR）：
   - stage：`CREATED｜SCRIPT_PARSED｜ASSETS_INDEXED｜IMAGE_PROMPTS_READY｜VIDEO_PROMPTS_READY｜REVIEWED｜DONE`
   - video_input_mode：`asset_reference｜text_only｜hybrid`
   - confidence：`confirmed｜inferred｜unknown`
   - 异常处理：`终止｜挂起｜已询问用户`
4. **冲突不覆盖**：任何两处结构冲突（状态 ↔ 源文件、台账 ↔ 资产表）→ 源文件优先 + 标记冲突（见【四、引用完整性】第 4 条）

## 一、状态文件｜`状态/流程状态.json`（流程层）

```json
{
  "schema_version": "1.0",
  "updated_at": "2026-10-11T15:30:00+08:00",
  "units": {
    "第1集": {
      "stage": "VIDEO_PROMPTS_READY",
      "stages_done": ["CREATED", "SCRIPT_PARSED", "ASSETS_INDEXED", "IMAGE_PROMPTS_READY", "VIDEO_PROMPTS_READY"],
      "stages_skipped": [],
      "video_input_mode": "asset_reference",
      "artifacts": {
        "segments": {"path": "第1集/", "version": 1, "verified": true},
        "asset_table": {"path": "资产表.txt", "version": 1, "verified": true},
        "image_prompts": {"path": "资产图提示词/人物场景提示词表.txt", "version": 1, "verified": false},
        "asset_images": {"path": "第1集/资产图/", "complete": false},
        "video_prompts": {"path": "第1集/", "version": 2, "verified": false}
      },
      "failures": [],
      "history": [
        {"time": "2026-10-11T15:10:00+08:00", "stage": "SCRIPT_PARSED", "action": "拆分完成", "result": "通过（校验器 0 ERROR）"}
      ]
    }
  }
}
```

字段约束：

| 字段 | 必填 | 结构 | 说明 |
|---|---|---|---|
| schema_version | ✓ | "1.0" | 结构版本 |
| updated_at | ✓ | ISO 8601 | 每次写入刷新 |
| units.<unit名> | ✓ | 对象 | unit 名 = 集文件夹名 |
| .stage | ✓ | stage 枚举 | 当前阶段 |
| .stages_done | ✓ | 数组 | 顺序与状态机一致 |
| .stages_skipped | ✓ | 数组 | 跳级执行的阶段（允许空数组） |
| .video_input_mode | 视频阶段起 | 枚举 | 未定则 `null` |
| .artifacts | ✓ | 对象 | 每项 `{path, version, verified}`；`asset_images` 用 `{path, complete}` |
| .failures | ✓ | 数组 | 每项 `{time, stage, reason, action}` |
| .history | ✓ | 数组 | 每项 `{time, stage, action, result}` |

## 二、状态文件｜`状态/连续性台账.json`（业务层）

只记「会变化的事实」（服装/持有物/位置/身体状态/时间线节点/段尾交接状态）；静态资产清册以 资产表 为准，不重复。

```json
{
  "schema_version": "1.0",
  "updated_at": "2026-10-11T15:30:00+08:00",
  "facts": [
    {
      "id": "第1集.ARES.costume",
      "unit": "第1集",
      "subject": "人物:ARES",
      "field": "costume",
      "value": "黑铜胸甲+酒红斗篷；段2结尾左肩负伤缠绷带",
      "source": "剧本:1-2",
      "confidence": "confirmed",
      "verified": true,
      "version": 2,
      "updated_at": "2026-10-11T15:20:00+08:00"
    }
  ],
  "conflicts": [
    {"id": "第1集.ARES.costume", "a": "台账:未负伤", "b": "剧本:1-3 负伤", "status": "open", "time": "2026-10-11T15:25:00+08:00"}
  ]
}
```

字段约束：

| 字段 | 必填 | 说明 |
|---|---|---|
| facts[].id | ✓ | `unit.主体.字段`——同一事实唯一 id，更新即新版本，不新增重复行 |
| facts[].subject | ✓ | `人物:<名>｜道具:<名>｜场景:<名>｜时间线` |
| facts[].field | ✓ | 见下方字段词典 |
| facts[].value | ✓ | 一句话事实；数值/状态/位置 |
| facts[].source | ✓ | 来源标注（通用规则第 2 条） |
| facts[].confidence | ✓ | `confirmed｜inferred｜unknown` |
| facts[].verified | ✓ | 用户确认过 = true |
| facts[].version | ✓ | 每次实质修改 +1 |
| conflicts[] | 可空数组 | `{id, a, b, status: open｜resolved, time}` |

**field 字段词典**（超出词表需在 value 中写清）：`costume`（服装）｜`appearance`（外形锚定/伤妆等外貌状态）｜`prop_hold`（持有）｜`prop_state`（道具状态/流转）｜`location`（位置）｜`state`（身体/情绪关键状态）｜`timeline`（时间节点）｜`relationship`（关系变化）｜`end_state`（段尾交接状态，value 写齐 人物位置/道具持有/光线时段）

## 三、交付物结构

### 3.1 拆分产物（SCRIPT_PARSED）

- 结构：`工作区/<集>/<集>-<段>`（默认规则；自定义格式以 `规范/自定义拆分格式规范.txt` 为准）
- 每集一个 `资产图` 文件夹；内容 = 剧本原文（只读源，禁止改写）
- 段落编号连续无跳号；上下段衔接状态可追溯（段尾 = 下段起点）

### 3.2 资产表（ASSETS_INDEXED）

分区顺序固定：`场景 → 人物 → 道具`（道具在最下）。字段：

| 分区 | 字段 | 必填 | 说明 |
|---|---|---|---|
| 场景 | 集范围＋资产名 | ✓ | 资产名=简短起名，唯一稳定 |
| 人物 | 名字＋性别＋大概服装 | ✓ | 服装写初始/主要形态；变体另起一行 |
| 道具 | 名字＋所属集＋一句话外观 | ✓ | 外观必须含表面材质与状态（来源标注沿用 理解模块） |

### 3.3 资产图提示词（IMAGE_PROMPTS_READY）

- 文件：`资产图提示词/人物场景提示词表.<ext>`（txt 默认；格式遵 人物图片资产格式.txt）
- 人物条目必含：头肩四宫格描述＋服装三视图描述＋负面提示词；参数取自四库+联动（可溯源）

### 3.4 提示词文件（VIDEO_PROMPTS_READY）

**槽位契约（顺序固定）**：

```text
【资产参考】→【场景】→【站位设计】→【人物】→【道具】→【拍摄参数】→【影调】→【人物情绪时间轴】→【镜头1..N】→【逻辑约束】→【负面提示词】→【声音时间轴】
```

| 槽位 | 必写性 | 校验 |
|---|---|---|
| 【资产参考】 | 有资产图（asset_reference/hybrid）必写；text_only 整节省略 | 声明行格式 `xxx:图片.文件格式`；引用文件存在（WARN） |
| 【场景】【站位设计】【人物】【影调】【人物情绪时间轴】【逻辑约束】【负面提示词】【声音时间轴】 | 必写 | 缺失 = ERROR |
| 【道具】【拍摄参数】 | 按需（有则写） | 缺失 = INFO（不阻断） |
| 【镜头N】 | 必写 ≥1 | 编号连续、不重复（重复 = ERROR，跳号 = WARN） |

**镜头N 内部字段**（参照 基础格式）：编号＋时码/动作名/台词编号、拍、构图描述、景别、焦点、运镜、动作、道具、背景、表情、台词、声音、特效、光线设计——必要项按 基础格式 执行。

**硬指标（机器校验）**：

1. 单段提示词全字符数（含标点与换行）≤ 9950（上限；可经 `校验配置.json` 调整）
2. 图片引用仅允许出现在【资产参考】节——其下方正文出现 `图片.文件格式`／`@` 图片引用 = ERROR
3. **跨段引用禁令**：禁止 `与第N段一致／延续第N段／同第N段基准／同链／衔接第N段／见第N段` 等引用语——承接状态必须就地展开写全
4. 2D 站位图信息不得以文件名/图例形式进入正文（出现「站位图」字样 = WARN 复核）
5. 台词逐句带语气标注（语速词），不得过快（设计期人工项）
6. **语言风格**：文字简洁、命令式（祈使句）、语气明确——直述可执行指令，禁止文学化描写与模糊表达（同 基础格式 注意事项 8；设计期人工项，不机械强检）

### 3.5 阶段任务（Task）

= 流程状态.json 中单 unit 的阶段记录：`unit + stage + artifacts + validators 结果 + failures`。恢复与重跑以 Task 为准（见 流程状态机【四、失败恢复】）。

## 四、引用完整性（跨表校验）

1. **资产引用**：提示词【资产参考】声明的每个资产 → 对应图片文件可寻（工作区内按文件名匹配；找不到 = WARN，提示补图或核对命名）
2. **镜头引用**：镜头引用的角色与道具 → 必须出现在该段清点名单内（设计期 Agent 自检；校验器做重复/连续性机械检查）
3. **状态引用**：台账 facts.source 必须可回溯到剧本/用户/资产表——不可回溯 = ERROR（校验器）
4. **冲突处理**：状态 ↔ 源文件 / 台账 ↔ 资产表 不一致 → 以源文件为准，标记 `conflicts`，严重时按 `规范/异常设计.md` 写入并询问用户；**禁止静默覆盖**

## 五、校验器检查编号对照

机械检查编号（`工具/校验器.py`，详见 `工具/校验器.md`）：状态层 `DS-*`｜结构层 `WS-*`｜资产表 `AT-*`｜提示词 `P-*`｜阶段门禁 `GATE-*`。本节各「校验」列与检查编号一一对应；新增检查必须先在本契约登记再进校验器。
