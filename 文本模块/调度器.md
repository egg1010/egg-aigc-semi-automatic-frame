# 文本模块调度器（TEXT MODULE DISPATCHER）

**作用域**：仅限文本模块操作
**交互模式**：全程提供选项（点选为主，自定义输入为辅）——规则见【交互规则】

## 交互规则（发起选项，而非文本输入）

AI 在执行前必须**主动向用户发起选项**（按钮式点选），不要求用户输入文本指令：

| 场景 | 发起的选项 |
|---|---|
| **用户啥都没说**（独立调用本文件） | **全选项表**（见下，零输入入口） |
| 文本拆分前 | 范围选项：所有集 / 第 x1集 到 第 x2集 / 自定义输入 |
| 拆分参数 | 分段时长选项：默认 30秒 / 60秒 / 45秒 / 自定义输入 |
| 找不到剧本 | 剧本来源选项：提供剧本路径 / 上传剧本 / 取消 |

**全选项表**（用户逐项点选）：

1. 操作类型：只读剧本理解 / 文本拆分 / 资产表
2. 范围：所有集 / 第 x1集 到 第 x2集（拆分与资产表时显示）
3. 分段时长：默认 30秒 / 自定义输入（拆分时显示）

- **每个选项必须附带「自定义输入」**：点选 + 补充输入 → 合并执行；纯文本输入 → 直接按用户要求执行
- 取消 → 跳到 收尾，正常结束
- **例外**：由 全局调度器 调用且指令完整（操作/范围/参数齐全）→ 直接执行，不发起选项；参数缺失时只发起缺失项的选项

## 架构文件缺失处理

- ★ 启动必读：第一步运行 根目录 `跟新规范.md`（每次重新阅读规范与全部格式文件，含 `规范/流程状态机.md`、`规范/自定义拆分格式规范.txt`；寻找与异常规则见该文件）
- 运行中访问的架构文件（`文本模块/理解模块.txt`、`文本模块/文本拆分模块.md`、`文本模块/资产表模块.md`）预设路径不存在 → **先尝试寻找**（工作区范围内搜索同名文件）→ 确实找不到才异常：按 `规范/异常设计.md` 写入 `AI数据/异常/日期异常.md` → 直接终止运行（不编造路径、不用默认顶替、不跳过继续）

## 状态与门禁

- 启动状态判定：读工作区 `AI数据/状态/流程状态.json`（缺失 → `python 工具/校验器.py init <工作区> --unit <单元>`）→ 确定 unit 当前阶段；对应阶段已完成且产物版本未变 → 默认跳过（用户明确要求重做 → 强制重跑，版本 +1）
- 阶段收尾（硬性）：文本拆分完成 → 写 `SCRIPT_PARSED`；资产表完成 → 写 `ASSETS_INDEXED`
  1. 写状态：`python 工具/校验器.py advance <工作区> --unit <单元> --stage <阶段> [--artifact 名称=相对路径 ...]`（版本自增）
  2. 跑校验：`python 工具/校验器.py check <工作区> --stage <阶段> --unit <单元>`
  3. 在对话输出阶段执行报告
- 校验 ERROR 未清零 → 不得对外宣布完成，先修复；无法修复 → 按 `规范/异常设计.md` 处理
- 阶段契约与失败策略见 `规范/流程状态机.md`；状态文件结构见 `规范/数据契约.md`

## 步骤

1. 零输入（独立调用）→ 发起 全选项表 → 按点选结果执行 2／3／4
2. 只读剧本理解 → 运行 `文本模块/理解模块.txt` → 阅读剧本（在工作文件夹下查找剧本）
   - 如果没有找到剧本 → 发起 剧本来源选项；取消 → 跳到 收尾
   - 理解输出含【MATERIAL MEMORY 材质识别】结果（道具材质/场景材质/服装面料/材质状态，含来源标注）→ 按场次在上下文内持有，后续供 联动模块 参数设计表逐行调用（不落盘）
3. 文本拆分 → 发起 范围选项 + 分段时长选项 → 执行 `文本模块/文本拆分模块.md`
   - 拆分格式：默认规则（工作区/x/x-a + 每集一个 资产图 文件夹）；自定义格式以 `规范/自定义拆分格式规范.txt` 为准（空=默认）
   - 完成后 → 按【状态与门禁】写 SCRIPT_PARSED + 校验器；同时抽取关键连续性事实初版写入台账（fact 命令，来源标 `剧本:<集>-<段>`）
4. 资产表 → 执行 `文本模块/资产表模块.md`（范围沿用第 3 步点选结果）
   - 完成后 → 按【状态与门禁】写 ASSETS_INDEXED + 校验器
5. ★ 结构化候选输出（记忆层接入，硬性）：除业务交付文本外，必须额外产出结构化候选并交执行器——**不得自行写库**
   - 人物 ID、场次 ID、道具 ID、位置 ID（供跨段引用与状态追踪）
   - `character/prop/location` 各实体的属性定义（外观/服装/材质等）
   - 带原文证据的 `event_proposals`（每条附 `evidence_chunk_id` 与原文引文）
   - `certainty` 分级：`explicit`（明确事实，可进审批队列）/ `inferred`（推断，默认不进正式状态，需用户确认）/ `unknown`（不得进入）
   - 同一事实重复出现时使用**幂等键**，避免重复事件
   - 禁止把生成的结论直接提交为正式事实；提交由执行器经审批在事务内完成
   - 命令：`python runtime/main.py extract --project <项目id> --chunk <证据块id>`
6. 无法归类的请求 → 发起选项让用户明确；仍无法判定 → 异常 → 收尾

## 收尾

1. 无异常 → 除状态文件与业务交付物外不写任何文件，正常结束（状态写入按【状态与门禁】）
2. 有异常 → 按 `规范/异常设计.md` 写入 `AI数据/异常/日期异常.md`（失败同时写入状态 `failures`）
